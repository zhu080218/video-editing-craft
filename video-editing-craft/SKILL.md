# 剪辑手艺

## 三句话

- **剪辑不是剪画面，是剪「观众还想不想看」。** 所有技巧都在跟那根划走的手指抢时间。
- **决定先写成数据，再交给一条命令。** 剪辑决策单（EDL）没落纸就开剪，等于用感觉返工。
- **只允许一次编码。** 每多压一遍，画质就被偷走一点，而且找不回来。

## 一、先分流

| 任务 | 判断依据 | 走哪条 |
|---|---|---|
| A 口播重剪 | 有说话人、有音轨 | 第三节 A |
| B 多素材叙事 | 多个片段 / B-roll / 无口播 | 第三节 B |
| C 工艺修复 | 片子已成型，只是糊、抖、吵、字幕乱、比例错 | 第三节 C |
| D 平台适配 | 一条成片要发多平台 / 改竖屏 | 第三节 D |
| 从零生成素材 | 只有脚本或想法 | 交给 `doubao-creative-video`，本技能只做后期 |

素材不在本地或读不到时，先问路径，不要猜文件名。

## 二、铁律（八条，都带数字）

1. **不动源文件。** 产物一律写到 `<源目录>/edit/`，源文件只读。
2. **先体检再动手。** `ffprobe` 看时长、帧率（是否 VFR）、旋转元数据、采样率、码率；手机竖拍常见 1920×1080 + rotation=-90，按显示尺寸算，不按编码尺寸算。
3. **只转写一次。** 词级时间戳存成 JSON 放源文件旁，之后所有决策（静音、口头禅、字幕、切片）都读这同一份。重转写 = 丢掉一致性。
4. **不切在词中间。** 切点两侧留 30–200 ms padding；音频接缝加 ~30 ms `afade`，否则每刀都「咔」一下。
5. **EDL 先落地。** 写成 `{source, in, out, note, speed}` 的表格，给人看一眼再渲染；改动只改 EDL，不重新想一遍。
6. **单次编码。** 切、拼、字幕、封面、变速在一条 `filter_complex` 里做完；禁止「先切一版 → 再烧字幕 → 再压一版」。
7. **720p 预览 → 最多 3 轮自修 → 1080×1920 定稿。** 看的是**渲染出来的成片**，不是源素材。
8. **字幕是最后一个视觉操作。** 时间轴用输出时间轴（剪完之后的时间），不是源时间。

## 三、工作流

### A 口播重剪

体检 → 转写 → 删（长静音 > 0.8s、口头禅、重复 take、句内口吃）→ 按「论点」重排而非按录制顺序 → 补 B-roll/图卡 → 字幕 → 响度 → QA。

- 删的比例目标：原始 100% → 成片 45%–65%，低于 40% 说明话太密，观众跟不上。
- J cut（声先入）/ L cut（声后出）各用 1–2 处，用来藏接缝。
- 每个论点开头给一个「钩子句」，直接说结论，再说理由。

### B 多素材叙事

素材盘点（按场景/人物/时间建索引）→ 场景边界检测 → 跨素材去重（重复镜头只留最好的那条）→ 选段 → 按节拍落轨 → B-roll 覆盖 → 音效 → 调色统一 → QA。

- 节奏曲线：前 3 秒每 1–1.5 秒一切；中段 3–4 秒一切；高潮前放慢到 5–6 秒，制造呼吸。
- 转场能用「动作匹配 / 视线匹配 / 图形匹配」就不用特效转场。一条片子特效转场 ≤ 2 处。

### C 工艺修复

先填诊断表，再一次只改一项：

| 症状 | 主因 | 最小改动 |
|---|---|---|
| 糊 | 二次压缩 / 码率不足 | 从原始素材重出，8–12 Mbps |
| 抖 | 手持 / 稳定裁切过度 | 轻稳 + 留 10% 余量再裁 |
| 色偏 | 白平衡错 / 混合光源 | 先校白点，再统一 LUT，不逐镜乱调 |
| 声音忽大忽小 | 未做响度归一 | 全片 -14 LUFS，真峰 ≤ -1 dBTP |
| 字幕压脸 / 被 UI 挡 | 未过安全区 | 上留 12%、下留 20% |
| 比例错 | 直接拉伸 | 跟踪重构（跟人脸/主体），不居中硬裁 |

### D 平台适配

- 9:16 用**跟踪重构**：主体横向漂移时让裁切窗跟着走，不要固定居中。
- 首帧即封面：选信息量最大的一帧，别用黑场或片头 logo。
- 一条母版 + 多平台导出，别为每个平台各剪一版。

## 四、平台守门（抖音 / 小红书 / 视频号）

| 项 | 参数 |
|---|---|
| 画布 | 1080×1920，30 fps（源 60 fps 保留给慢动作） |
| 编码 | H.264 / yuv420p / 8–12 Mbps / AAC 48 kHz |
| 字幕 | 中文 4–9 字/秒（CPS ≤ 9），单行 ≤ 14 字，最多 2 行 |
| 安全区 | 上 12%、下 20% 不放关键信息 |
| 响度 | -14 LUFS ±1，真峰 ≤ -1 dBTP |
| 时长 | 抖音 15–45s 最优；小红书 30–90s；视频号 30–60s |
| 章节 | ≤ 4 个，每名 2–4 字，写进描述，**不烧进画面** |

## 五、验收（不达标的片子不交付）

- 3 秒留存 ≥ 60%，完播率 ≥ 40%（≤60s 片子）——发布 24h 后看后台，不靠感觉。
- 切点无黑帧、无重复帧；成片时长与 EDL 计算值偏差 ≤ 0.1s。
- 字幕零错字、零越界、CPS ≤ 9。
- 响度达标；任意 1× 带声看完不觉得「哪里不对」。

## 六、常见失败与修法

1. 前 3 秒在自我介绍 → 改成直接抛结论或抛冲突。
2. 全片一个节奏 → 至少做三个速度段（快 / 中 / 慢）。
3. 字幕逐字蹦 → 改成词组级（2–6 字一闪），跟随语流。
4. BGM 盖过人声 → BGM 压到 -24 LUFS 左右做底，人声永远最响。
5. 转场堆特效 → 删到 ≤ 2 处，其余用硬切。
6. 调色一套 LUT 通吃 → 先统一曝光与白平衡，再上风格。
7. 一条片子压了四遍 → 回到第 6 条铁律，重出一次。
8. 无限改 → 改满 3 轮仍不满意，回到 EDL 层重排结构，而不是继续微调。

## 七、脚本

`scripts/edl_check.py`：校验 EDL 与字幕表，纯 Python、无需 FFmpeg。检查片段逆序/重叠/过短、切点 padding、字幕重叠、CPS 超限、单行过长。

```bash
python scripts/edl_check.py --edl edl.json
python scripts/edl_check.py --edl edl.json --fps 30 --min-seg 0.3 --padding 0.05 --cps-max 9
```

输出每段时长、总时长、告警清单；退出码 1 表示有阻塞级问题，先改 EDL 再渲染。

## 八、自检清单

交付前逐条打勾：源文件没动 / 有 ffprobe 体检记录 / 转写只做一次 / EDL 与成片时长对得上 / 只编码一次 / 720p 预览看过 / 字幕过安全区且 CPS ≤ 9 / 响度达标 / 平台参数对 / 留了可复现配方。
